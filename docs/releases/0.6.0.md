# Borecount 0.6.0

This is the first coordinated Borecount release, following LuxLedger `0.5.0`.

| Artifact | Version |
| --- | --- |
| `@borecount/core` | `0.6.0` |
| `@borecount/http` | `0.6.0` |
| `@borecount/postgres-adapter` | `0.6.0` |
| `@borecount/fastify-routes` | `0.6.0` |
| `@borecount/express-routes` | `0.6.0` |
| OpenAPI `info.version` | `0.6.0` |

## Package and repository names

Install packages under `@borecount/*` and use that scope in every import. Supported
package subpaths keep their layout. Consumer Drizzle configuration imports
`borecountDrizzleSchemaPath` from `@borecount/postgres-adapter/drizzle-config`.

This release is a direct cutover: old package names and
`luxLedgerDrizzleSchemaPath` have no compatibility aliases or deprecation window.
Old published artifacts and historical release notes are not rewritten.

The canonical repositories are [Borecount](https://github.com/Borecount/Borecount)
and [Borecount-demo](https://github.com/Borecount/Borecount-demo). Existing Git
history is preserved.

## Behavior and data

Ledger invariants, HTTP paths/statuses/bodies, PostgreSQL schema and migrations
are unchanged from the published `0.5.0` baseline. No migration is added, changed
or removed in this release. Existing local database names, users, Docker
containers, volume names and backup identities remain unchanged; do not recreate
or rename them as part of the rebrand.

The PostgreSQL bootstrap-admin advisory-lock namespace also remains unchanged
because it coordinates access to existing database state.

For a local demo checkout, replace package dependencies/imports with the complete
`0.6.0` set and regenerate its lockfile. No data conversion is required.
