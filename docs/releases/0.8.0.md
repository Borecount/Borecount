All five public `@borecount/*` packages and the OpenAPI contract ship as `0.8.0`.

| Component | Version |
| --- | --- |

## Changes since 0.7.0

- **Tenant provisioning (LL-116):** hosts can provision a tenant and its initial admin API key atomically, including within a host-owned unit of work. Bootstrap uses the same provisioning flow.
- **Adjustment authorization (LL-119):** both adapters can call host policy on every adjustment, including retries. The callback resolves the trusted actor and the adapter checks it against the request's `actor_id`.
- **Errors and resource protection (LL-134):** centralized domain errors, shared 429 responses and optional `Retry-After`, and documented generic 413 responses. Rate limiting and request-size enforcement belong to the host. Express supports a custom JSON parser or an explicit parser opt-out.
- **Self-hosted security (LL-136):** added an opt-in least-privilege PostgreSQL overlay with tenant RLS, separate credential lookup, and safer database error reporting. See the [security setup guide](../integration/self-hosted-security.md).
- **Backup and restore (LL-135):** added portable PostgreSQL backup bundles with snapshot and integrity metadata, plus verified restore into an isolated recovery cluster. See the [operator runbook](../runbooks/portable-backup-restore.md).
- **Tenant assets (LL-117):** authenticated clients can list and look up tenant assets under `/v1/assets`. Tenant admins can create assets. Asset lists support typed filters and scoped cursors.
- **Reconciliation history (LL-118):** added upload lookup, paginated upload and run lists, and normalized records per upload. Run history captures the matching rules used by each run. The new indexes support filtered history reads.

## Upgrade from 0.7.0

1. Upgrade all five packages together, regenerate the consumer lockfile, and update the OpenAPI copy.
2. Register Fastify or Express with `registerLedgerAdapter` and supply `authorizeAdjustment`. Use the host's authorization callback, or pass `false` for a trusted integration that owns actor authorization. Keep `actor_id`, metadata, and the rest of the command stable on retries. See the [adjustment guide](../integration/adjustment-authorization.md) and [idempotency reference](../integration/idempotency.md).
3. Import custom errors and guards from `@borecount/core/errors`. Use `toHttpErrorPayload` in place of `mapDomainErrorToHttp` and `HttpErrorDto`. Its result separates `statusCode`, `headers`, and `body`. Use the canonical `RateLimitExceededError` for 429. Construct the `INVALID_INPUT` response directly if you used `invalidInputPayload`. Update clients that expect 400 for posting to a missing account to handle 404.
4. Supply UUIDv7 IDs when provisioning tenants. Existing resource UUIDs remain version-neutral. Custom reconciliation repositories must implement `getUpload`, `listUploads`, `listRuns`, and `listRecords`. Custom HTTP integrations should use the shared hold schemas and route contracts in place of removed route base classes and pagination wrappers.
5. Restart paginated reads from the first page. The shared scoped cursor format uses six-digit timestamps. Typed timestamp filters compare at millisecond precision for inputs with up to three fractional digits and at exact PostgreSQL precision for finer inputs. Response timestamps retain millisecond precision.
6. If adopting the security overlay, configure the separate authenticator connection and pass it to `createApplicationServices(runtimeClient, lookupClient)`. Test tenant isolation, authentication and key management with the real runtime roles.

## PostgreSQL baseline reset

The published 0.7.0 chain ran from `0000_initial-schema.sql` through `0007_2026-10-17-partial-credit-grant-refund-functions.sql`. Version 0.8.0 replaces that pre-production chain with these migrations, in order:

1. `0000_2026-11-09-baseline.sql`
2. `0001_2026-11-10-reconciliation-run-rules-and-history-indexes.sql`
3. `0002_2026-11-10-reconciliation-filtered-history-indexes.sql`

Apply this chain to an empty database. Recreate disposable dev/test databases. For existing data, verify a restorable backup with the matching 0.7.0 checkout and retain its migration history. This baseline reset has no supported in-place upgrade for 0.7.0 databases. Keep data-bearing installations on their current version until a separately validated migration is available. See the [migration policy](../integration/versioning.md).
